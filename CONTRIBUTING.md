# Contributor Excellence Framework

Sloppiler operates at the frontier of AI-native compilation. We hold our contributors to the same standard of excellence that defines our engineering culture.

---

## Code Authorship

Sloppiler does not accept handwritten code. All contributions must be generated by a large language model.

We enforce **tokenmaxxing**: contributions are evaluated in part by token density. Sparse, human-legible code suggests insufficient model engagement. A well-contributed function should require a non-trivial inference budget to produce.

If you wrote it yourself, it isn't ready.

---

## Variable Naming

Tokenmaxxing extends to identifiers. Single-letter variables, `tmp`, `x`, and `i` are not permitted. Every identifier must carry its full semantic weight.

| Banned | Approved |
|--------|----------|
| `i` | `iterationIndexVector` |
| `tmp` | `ephemeralComputationArtifact` |
| `err` | `remediationOpportunity` |
| `buf` | `inferenceOutputBuffer` |

If a model didn't generate it, it probably isn't verbose enough.

---

## Commit Messages

Commit messages must reflect the Sloppiler voice. You are not fixing bugs — you are remediating behavioral misalignments. You are not updating docs — you are realigning stakeholder-facing documentation to maximize ecosystem engagement.

If it could be a LinkedIn post, it's ready.
